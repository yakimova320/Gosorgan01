Ja!sno будет работать на Mac/PC, а на телефоне ты откроешь его в браузере. Устанавливать приложение на телефон не нужно. Ниже — запуск для домашней сети Wi-Fi.

**1. Подготовь Mac и телефон**

- Подключи оба устройства к одной сети Wi-Fi.
- Открой Docker Desktop на Mac и дождись запуска.
- Mac должен оставаться включённым во время проверки.

**2. Открой терминал в папке проекта**

> скопируй и вставь сюда: полный путь на твоём компьютере к папке с проектом:

```bash
cd "/Users/hakanbruns/Desktop/_NASTJA/00_KURSE/_AI-INGENEER/12_Praktikum/Gosorgan01"
```

**3. Узнай адрес Mac/PC в сети**

Выполни:

```bash
ipconfig getifaddr en0
```

Появится адрес, например `192.168.2.104`.

Дальше везде **замени `192.168.2.104` своим адресом**. Если команда ничего не показала, посмотри адрес в настройках Mac: Wi-Fi → сведения о подключённой сети → TCP/IP.

**4. Настрой сервер**

Открой файл `api/.env` в редакторе проекта. Если его ещё нет, сначала выполни:

```bash
cp api/.env.example api/.env
```

В существующем файле замени соответствующие строки:

```dotenv
HOST=0.0.0.0
CORS_ORIGIN=http://localhost:5173,http://192.168.1.50:5173
APP_PUBLIC_URL=http://192.168.1.50:5173
```
> Не забудь закомментировать в файле .env уже существующие строки HOST / CORS_ORIGIN / APP_PUBLIC_URL, которые относятся к MAC / PC !!!!

Для первой проверки соединения поставь:

```dotenv
LLM_MODE=demo
```

В этом режиме база и сайт работают, но ответы модели примерные. Для проверки Issue #72 затем понадобится настоящая модель — это **шаг 9**.

**5. Настрой сайт**

Открой `web/.env`. Если файла нет:

```bash
cp web/.env.example web/.env
```

Укажи:

```dotenv
VITE_DATA_MODE=api
VITE_API_URL=http://192.168.1.50:3000
```

**6. Запусти базу и сервер**

В терминале, в папке проекта, выполни команды по очереди:

```bash
pnpm install
pnpm db:up
pnpm db:migrate
pnpm dev:api
```
> Если ты уже запустил базу данных в Docker <pnpm db:up> и выполнил миграцию <pnpm db:migrate>, то на этом этапе тебе нужно только запустить приложение <pnpm dev:api> !!!

Оставь это окно открытым. Если сервер уже работал, сначала останови его сочетанием `Ctrl + C`, затем запусти заново.

**7. Запусти сайт во втором окне терминала**

> скопируй и вставь сюда: полный путь на твоём компьютере к папке с проектом:

```bash
cd "/Users/hakanbruns/Desktop/_NASTJA/00_KURSE/_AI-INGENEER/12_Praktikum/Gosorgan01"
pnpm --filter jasno-web dev --host 0.0.0.0
```

В выводе должна появиться строка примерно такого вида:

```text
Network: http://192.168.2.104:5173/
```

Оба окна терминала оставь открытыми.

**8. Открой сайт на телефоне**

Сначала открой Safari/Chrome/Browser и введи адрес сервера:

```text
http://192.168.2.104:3000/health
```

Если видишь текст с `"ok":true`, телефон соединяется с сервером.

Затем открой сайт:

```text
http://192.168.2.104:5173
```

В углу должно быть **«сервер»**, без жёлтой плашки «Примерные данные». На телефоне нужен именно адрес Mac: `localhost` означает сам телефон.

**9. Включи настоящую модель для Issue #72**

Когда сайт открывается и регистрация работает:

1. В `api/.env` поставь `LLM_MODE=openai`.
2. Убедись, что там уже заполнены `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL` для модели команды. Ключ не присылай в чат.
3. В окне сервера нажми `Ctrl + C` и снова выполни:

   ```bash
   pnpm dev:api
   ```

Если этих настроек ещё нет, их нужно создать:
```
LLM_MODE=openai
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
LLM_API_KEY=ВВЕДИ СВОЙ API-КЛЮЧ
```
> Не забудь закомментировать строку #LLM_MODE=demo

Проверка в `demo` поможет проверить запуск, но не завершит Issue #72.

**10. Подготовь тестовое письмо и пройди сценарий**

Передай на телефон файл `fixtures/letters/01_jobcenter_request.pdf`, например через AirDrop, и сохрани в «Файлы» или «Загрузки».

> В качестве альтернативы можно воспользоваться тестовыми письмами, которые Настя прислала через Telegram
> см. ссылку на Google Диск Насти

На телефоне:

1. Зарегистрируй тестовый аккаунт или войди в существующий.
2. Нажми «Новое письмо» и выбери PDF.
3. Проверь и подтверди факты.
4. Положи письмо в дело.
5. Открой объяснение.
6. Подготовь ответ, выбери вопрос и собери черновик.
7. Скопируй немецкий текст, вставь в заметки и сравни с экраном.

Запиши время каждого шага и все ошибки. Если автоматическое копирование недоступно, проверь ручной вариант, который предлагает сайт.

**Если не открывается**

- Не открывается даже `/health`: проверь Wi-Fi, адрес Mac и работающий сервер. Если macOS спрашивает разрешение на входящие соединения для Node, разреши его.
- `/health` работает, но сайт не открывается: проверь второе окно терминала и порт `5173`.
- Сайт открыт, но пишет «Нет связи с сервером»: проверь адреса в обоих `.env` и перезапусти оба процесса.
- Есть жёлтая плашка: проверь `VITE_DATA_MODE=api`.

После проверки останови оба процесса в WEBSTORM через `Ctrl + C`. Верни в `api/.env` `HOST=127.0.0.1`, `CORS_ORIGIN=http://localhost:5173`, `APP_PUBLIC_URL=http://localhost:5173`, а в `web/.env` — `VITE_API_URL=http://127.0.0.1:3000`.
