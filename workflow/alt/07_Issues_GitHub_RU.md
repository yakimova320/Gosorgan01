## Как работать над любым Issue

1. Открой Issue в GitHub и нажми справа «Assignees → assign yourself».
2. Открой Claude Code в папке проекта.
3. Скопируй из Issue блок «Текст для Claude» целиком, впиши номер Issue вместо `___` и отправь.
4. Claude сначала покажет план. Если план понятен, ответь «да». Если нет, спроси, что значит непонятное слово.
5. Когда Claude закончит, пройди шаги «Как проверить» сам(а).
6. Claude откроет Pull Request (PR). Напиши проверяющему в чат команды ссылку на PR.
7. Проверяющий проходит «Как проверить» и пишет в PR «Проверено, работает» или что не так.
8. После этого Настя нажимает «Merge». Issue закроется сам.

Если что-то сломалось, не удаляй ничего. Скопируй текст ошибки целиком и отправь Claude с вопросом «Что это значит и как исправить?».

## Словарик

- Репозиторий: папка проекта в GitHub со всей историей изменений.
- Ветка: отдельная копия кода для одной задачи. Основная ветка называется `master`.
- Коммит: сохранённый шаг работы с коротким описанием.
- Pull Request (PR): просьба перенести изменения из своей ветки в `master`. Его смотрят и проверяют другие.
- Бэкенд: программа на сервере. Хранит данные, говорит с ИИ, отвечает на запросы.
- Фронтенд: сайт, который человек видит в браузере.
- Эндпоинт: адрес на сервере, по которому можно что-то попросить, например `POST /auth/login`.
- Swagger: страница `http://127.0.0.1:3000/docs`, где можно вручную вызвать любой эндпоинт.
- Postman: программа для отправки запросов к серверу и автоматических проверок ответов.
- База данных: место, где сервер хранит дела, письма и кабинеты. У нас SQLite для разработки и PostgreSQL для публикации.
- Prisma: библиотека, через которую сервер работает с базой. Схема таблиц лежит в `prisma/schema.prisma`.
- Токен сессии: длинная случайная строка, которую сервер выдаёт после входа. Браузер прикладывает её к каждому запросу.
- Статус-код: число в ответе сервера. 200 и 201 значат «получилось», 400 «неверные данные», 401 «не вошёл», 404 «не найдено», 409 «уже существует», 429 «слишком много попыток», 500 и 502 «ошибка на сервере».

### [A02] Александра: регистрация и вход по паролю
<!-- who=ALEXANDRA milestone=Н2 labels=person:alexandra,area:backend,prio:high -->

- `POST /auth/login`: вход.
- `POST /auth/logout`: выход.
- `GET /cabinet`, `PATCH /cabinet`, `DELETE /cabinet`: данные кабинета.
- Все остальные эндпоинты без токена отвечают 401.

#### Текст для Claude
