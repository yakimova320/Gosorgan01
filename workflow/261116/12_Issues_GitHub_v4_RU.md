## Как работать над Issue: Настя с Claude Code

1. Назначь Issue на себя.
2. Открой Claude Code в папке проекта. Скопируй «Общее начало для Claude» и под ним блок «Текст для Claude» из Issue. Впиши номер Issue вместо `___`.
3. Claude покажет план. Понятно: ответь «да». Непонятно: спроси.
4. Когда Claude закончит, пройди «Как проверить».
5. Claude открывает PR. Ссылку отправь Александре.
6. После её «Проверено» нажми «Merge». Issue закроется сам.

### Общее начало для Claude

```text
Я Настя, новичок в программировании, у меня дизайнерский опыт. Объясняй по-русски простыми словами.
Прочитай AGENTS.md и workflow/261116/11_TZ_ClaudeCode_v4_RU.md (разделы, указанные ниже).
Сначала обнови master из GitHub и создай ветку с именем из задачи.
Покажи план и подожди моего «да». Потом работай самостоятельно.
В конце: pnpm lint, pnpm typecheck, pnpm test, pnpm test:e2e, pnpm build, исправь ошибки, обнови docs/readiness.md.
Сделай коммит, отправь ветку, открой PR с «Closes #___», шагами проверки и скриншотами 390 и 1440 px, если менялся интерфейс.
```

## Как работать над Issue: Дмитрий (без ИИ)

1. Назначь Issue на себя.
2. Выполняй «Что сделать» по порядку, команды копируй целиком.
3. Ошибка: ничего не удаляй, скопируй команду и весь текст ошибки в комментарий к Issue.
4. Документы создавай на сайте GitHub: «Add file → Create new file», внизу «Create a new branch», «Propose changes», «Create pull request».

## Как работать над Issue: Геннадий (бесплатный ИИ, без репозитория)

1. Назначь Issue на себя.
2. Проект получаешь через GitHub Desktop: «Fetch origin», потом «Pull».
3. Коллекция: `api/postman/jasno.postman_collection.json` и `api/postman/local.postman_environment.json`. После каждого Pull импортируй заново, старую удали.
4. В бесплатный ИИ-чат нельзя вставлять файл `.env`, ключи и тексты настоящих писем.
5. Результат: комментарий в Issue (что запускал, сколько проверок зелёных и красных, скриншот Runner).

### Шаблон Issue об ошибке

```text
Заголовок: [BUG] <коротко, что не так>

Какой запрос или экран: <папка и имя запроса в Postman или адрес страницы>
Что ожидалось: <например, 401 INVALID_CREDENTIALS>
Что пришло: <статус-код и текст ответа целиком>
Как повторить: <шаги>
Версия: <дата Pull>
```

Метки: `bug` и `area:backend` или `area:frontend`. Исполнителя назначают Александра и Настя.

## Словарик

Словарик из версии 3 остаётся. Новые слова:

- Hard delete: удаление без возможности восстановить, без пометки «удалён».
- Токен восстановления: одноразовая ссылка из письма «Забыли пароль?».
- `MAIL_MODE=file`: письмо не уходит по почте, а сохраняется файлом в `api/storage/mail-outbox/`. Так можно проверить восстановление пароля без почтового сервиса.
- Чат-помощник: окно вопросов на сайте. Отвечает про Ja!sno, письма не разбирает.
- Карточка «Важно знать»: короткий проверенный совет с источником.
- demo и real: ответы без настоящей модели (для тестов) и с настоящей моделью.
