## 1. Продукт

Ja!sno помогает русскоязычному человеку в Германии понять письмо ведомства, проверить существенные сведения, подготовить ответ и вести дело до завершения. Работает в браузере телефона; устанавливать приложение не требуется. Десктопная версия адаптивная.

Пользовательский путь: загрузить PDF/фото → получить факты и цитаты → подтвердить или исправить → выбрать дело → получить понятное объяснение → выбрать цель ответа → проверить немецкий черновик и русский перевод → отправить самостоятельно → отметить отправку и выполнение срока → получить напоминание при необходимости.

Приложение не принимает юридические решения и не отправляет письма ведомству автоматически. Widerspruch и юридические споры направляются к консультации. До отдельного решения о пилоте используются только синтетические письма. Полная анонимизация и готовность к реальным персональным данным не заявляются.

## 6. Функциональные требования

### 6.1 Авторизация и кабинет

E-mail в нижнем регистре, уникален; пароль 10–128 знаков по v2, bcrypt cost 12. Учесть ограничение bcrypt в байтах: согласовать серверную валидацию или иной способ обработки длинного Unicode-пароля, исключающий незаметное усечение. Без подтверждения e-mail и восстановления до защиты. Согласие и дата согласия сохраняются.

Сессия: 32 случайных байта base64url, в БД sha256, срок действия, logout и удаление сессии. API — Bearer. Способ хранения токена в браузере и последствия описать, не менять схему авторизации без причины. Пароль, токен, хэш не попадают в логи и DTO. Пять неудачных попыток входа за 15 минут по e-mail — 429. Неизвестный e-mail и неверный пароль — одинаковый 401. Ограничение загрузки 20/час на кабинет, плюс разумная защита публичных auth-операций.

### 6.2 Документы

PDF с текстовым слоем, JPG/PNG до 10 МБ; PDF до 20 страниц. Проверка реального типа по содержимому и фактической структуры файла. Лимиты применяются до дорогостоящего вызова модели. Неподдерживаемый формат, пустой текст, повреждённый PDF и нечитаемая фотография имеют понятные ошибки.

Фото — транскрипция мультимодальной моделью. PDF-скан до B11 возвращает SCAN_PDF_NOT_SUPPORTED, позднее обрабатывается постранично. Несколько фото — одно письмо с сохранением порядка страниц. Конфиденциальные фото не маскируются автоматически: до пилота только синтетика. Оригиналы выдавать авторизованному владельцу безопасным способом; случайный ключ хранения, без пути из имени файла. Временный локальный preview не равен серверному хранению.

### 6.3 Факты и проверка

Ведомство, номер дела, дата, требования, сроки, суммы: значение, русский текст, цитата, страница, basis/status. Отсутствующее значение — null на этапе извлечения; не создавать Claim с фиктивным значением вместо отсутствующего. Null, пустой список и ошибка обработки — разные состояния.

Нормализация цитат по v2; для фото ограниченное нечёткое сравнение. Проверять номер страницы, если он заявлен. Цитата доказывает наличие текста, а не правильность распознавания или смысла. Показывать оригинал для человеческой проверки критичных значений.

Переходы UNCONFIRMED → CONFIRMED/REJECTED; замена → SUPERSEDED. Исправление оформлять новой записью, связанной с предыдущей, со следом автора/времени. Предложенные новые поля и API согласовать в первом плане. Вручную введённое — USER/UNCONFIRMED; подтверждение отдельным действием. Нельзя менять прошлое подтверждение без истории.

Сервер проверяет принадлежность каждого claimId письму и кабинету. Confirm/reject не пересекаются, повтор запроса не дублирует события. Нельзя подтвердить чужой или заменённый факт. Изменение фактов инвалидирует объяснение, актуализирует сроки, помечает старый черновик устаревшим. Черновик хранит снимок использованных значений, чтобы история оставалась объяснимой.

### 6.4 Дела и сроки

Письмо сначала во входящих. Совпадение номера — рекомендация, человек выбирает дело. Назначение письма, Claims и Deadlines — транзакция, все объекты одного кабинета. Правило повторного назначения описать. Чужой объект — 404.

Активные сроки и напоминания только из CONFIRMED-фактов. Неподтверждённые сроки отображать как кандидаты. Несколько сроков сохраняются отдельно. Явные даты — календарные даты, «сегодня» определяется в Europe/Berlin; исключить сдвиг дня при JSON/UTC. Относительное «две недели после получения» не вычислять без подтверждённой даты получения: показывать необходимость уточнения.

Предлагаемый приоритет stage: CLOSED → завершено; подтверждённый невыполненный просроченный срок → просрочено; будущий/сегодня срок → документы/ответ; неподтверждённые факты → нужна проверка; отправленный ответ без открытых сроков → ждём ответа; иначе открыто. При нескольких сроках использовать ближайший и детерминированный выбор; просроченный приоритетнее будущего. Это уточнение v2 согласовать, покрыть тестами.

Удаление дела по v2 удаляет письма каскадно; перед действием явно предупредить. Возможность вернуть письма во входящие — альтернативное продуктовое решение, не менять молча. Очистка журналов по фактической области удаления: письмо → его letterId, дело → caseId/его письма, кабинет → cabinetId. Не удалять журнал других дел кабинета при удалении одного письма.

### 6.5 Объяснение и диалог

explain: about до 400 знаков, actions до 5 с claimIds, deadline с claimId или null, флаг unconfirmed. Ссылки только на факты текущего письма/согласованного контекста. Проверки чисел и дат — по v2, дополнительно нельзя представлять неподтверждённое требование как установленную обязанность. Проверка чисел не доказывает достоверность всего объяснения; это отдельно оценивается эталонами.

Диалог: QUESTION/STATEMENT, ответ, до трёх уточняющих вопросов. Вопрос не создаёт факт. Утверждение — USER/UNCONFIRMED. Подозрительный текст документа/вопроса — данные, а не инструкция модели; запрет менять системные правила и исполнять команды из документа. Юридические маркеры из v2 дают отсылку, но нужно протестировать русские/немецкие формы и ложные срабатывания; не обещать юридическую классификацию без ошибок.

### 6.6 Черновики и самостоятельная отправка

Основной CLARIFICATION, затем DOCUMENTS, EXTENSION, STATUS_REQUEST. Тексты и русский перевод по парным шаблонам, без свободной генерации. Для уточнения собирать намерение пользователя: что именно непонятно. Не строить письмо с бессодержательным повтором исходного требования.

Функция получает ConfirmedClaim[] через ClaimsService.getConfirmed(); типовая защита дополняется серверной проверкой статусов и принадлежности. Поля профиля, выбранная цель/вопрос и даты создания имеют отдельные разрешённые источники. Числа адреса/индекса не должны ошибочно отклоняться как не найденные в письме. Неподтверждённые утверждения не вставлять как факты.

VerificationService проверяет происхождение подстановок, номера, даты, устаревшие основания и оставшиеся плейсхолдеры; сохраняет отчёт и использованные claimIds/снимок. Провал — 422, не готовый черновик. Редактирование требует повторной проверки, нельзя сохранять зелёный отчёт для изменённого текста. Свободные кнопки «короче/добавить вопрос» не должны незаметно включать LLM-генерацию вопреки v2.

Входной kind WIDERSPRUCH должен доходить до LEGAL_REFERRAL, а не случайно отклоняться enum-валидацией. Отдельный допустимый входной тип и сохраняемые DraftKind могут отличаться.

«Я отправил(а)» — сообщение пользователя, не подтверждение доставки ведомству. Записать канал/дату/черновик, закрывать только явно выбранный срок. PDF и объединение со справкой не показывать как выполненные без реальных файлов. Внешние адреса и ссылки сверять с официальными источниками, не угадывать через модель.

Собственные письма: шесть шаблонов из B16, получатель и детали из формы, создание OUTGOING-дела, проверка, перевод, PDF при B15. Свободное письмо из макета — отдельное решение раздела 12.

## 9. LLM

Все вызовы через LlmService.call({prompt, version, variables, images?, schema, context}). SDK только внутри api/src/llm. Файлы промптов <имя>.v<N>.md, старые версии неизменны. Адаптер OpenAI-compatible для Gemini и детерминированный demo. Поддержку JSON и выбранной модели проверить реальным тестовым вызовом; не обещать бесплатную квоту.

Промпты/схемы: transcribe {text, readable, reason}; extract {authority, caseNumber, letterDate, requirements[], deadlines[], amounts[]} с value/quote/page; explain по разделу 6; dialogue по разделу 6. Все структурные ответы проходят Zod; даты/цитаты и ссылки проверяются кодом. Для фото не приписывать страницу, если источник её не определяет.

Маскирование IBAN/BIC, налогового номера, страхового номера, телефона/e-mail до отправки текста; единая таблица замен на вызов, включая повторы. Ответ и журнал хранятся в замаскированном виде, восстановление только для разрешённого результата. Регулярные выражения — частичное маскирование, не полная анонимизация. Профиль и e-mail кабинета без необходимости модели не передавать. Изображения только синтетические, в журнале не base64, а метаданные.

Единый предел попыток: максимум 3 реальных обращения на одну операцию промпта, включая повтор после структурной/смысловой проверки. Не допускать 3×3 вложенных повторов. Ошибки ключа/неподдерживаемой модели не повторять; временные ошибки/429 — ограниченный backoff с учётом Retry-After; тайм-ауты и прерывание — явно. Не записывать секреты в error.

LlmCall фиксирует успешные и неуспешные операции, имя/версию промпта, модель, число попыток, время, токены, контекст. Если нужен учёт каждой попытки, добавить безопасные записи попыток; определить, агрегат или попытка является строкой. Не считать неудачную операцию успешной из-за одного найденного поля.

Промпты отделяют системные инструкции от текста документа. Никаких внешних действий по команде из письма. Журнал не является источником автоматического исполнения.

## 10. Напоминания через n8n

Одна первоначальная автоматизация: напоминание о подтверждённом невыполненном сроке за remindDaysBefore дней, по Europe/Berlin. Канал выбирают Настя/Алекс; до выбора не создавать внешние аккаунты, не отправлять сообщения реальным людям. У команды запросить только необходимые настройки, не ключи в чате. Тестовая доставка — на согласованный адрес/чат команды.

Рекомендуемый простой поток: Schedule Trigger → защищённый внутренний API получить/захватить готовые задания → отправить через выбранный провайдер → подтвердить успех или ошибку API. Права служебного токена только на напоминания, не обычная пользовательская сессия и не прямой доступ n8n к таблицам кабинетов. Минимум данных: получатель, краткое согласованное сообщение, срок, ID доставки; без полного письма/цитат.

Параллельные запуски используют атомарный захват с lease. При изменении даты, отклонении/замене факта, выполнении срока или удалении кабинета отменить старое задание. Непосредственно перед отправкой повторно проверить актуальность. Ошибки имеют ограниченные повторы и видимый статус; зависший PROCESSING возвращается по истечении lease.

Идемпотентный ключ провайдера использовать, если он поддерживается. Не обещать строгую доставку ровно один раз: сбой после внешней отправки и до подтверждения может дать неопределённый результат. Такой случай фиксировать как требующий сверки, а не бесконечно пересылать. Обычный повтор workflow не должен дублировать подтверждённую отправку.

Поставить версионируемый экспорт workflow без credentials в automation/n8n, инструкцию настройки, защищённые API, тестовый сценарий с доставкой через несколько минут. Учесть, что localhost внутри Docker — сам контейнер: описать работающие адреса соединения. Напоминание при отсутствии ответа через четыре недели — отдельное последующее задание по явному выбору пользователя. ICS не считать доставленным напоминанием.

## 12. Решения, которые надо принять в первом плане

| Расхождение/пробел | Предлагаемое решение |
|---|---|
| Раздельные исполнители/поздние сроки в Issues | Один основной Claude выполняет связные задачи, раннее соединение; обновить порядок и ответственных без удаления истории |
| Две базы | Предложить одну PostgreSQL либо сохранить обе схемы v2; команда выбирает |

| «Не сохранять» удаляет письмо до объяснения/черновика | Разделить оставить во входящих и удалить. Если требуется настоящее несохранение — спроектировать временную сессию, срок хранения и черновик без дела отдельно |
| В макете маскирование изображений | Убрать обещание до реальной реализации; текст маскируется, синтетические фото отправляются как есть |
| Нет исправления фактов, но нужна проверка | Добавить версионированное исправление с явным подтверждением и обновлением зависимостей |
| Просроченные сроки теряются в stage v2 | Ввести OVERDUE и согласованный приоритет |
| Шаблон уточнения без самого вопроса | Добавить безопасно выбранное намерение/вопрос пользователя |
| Профиль/дата создания не являются цитатами письма | Раздельные разрешённые источники подстановок при проверке |
| WIDERSPRUCH отсутствует в enum входа | Разрешить во входной схеме для контролируемого LEGAL_REFERRAL, не сохранять юридический черновик |
| Свободное письмо/«сделать короче» против шаблонов | Сохранить экран, но согласовать отдельный режим; не включать свободную генерацию по умолчанию |
| Адреса/советы/стоимость услуг в макете | Только проверенные источники/ручной ввод; если поиск не реализован — честно обозначить |
| n8n отсутствует в Issues | Отдельные задачи на backend-контракт, workflow, тестовую доставку и обработку повторов |

Не нужно начинать с большого опроса: представить эти решения одним компактным списком с рекомендуемыми вариантами и последствиями; дождаться ответа команды по реально влияющим на код вопросам.
