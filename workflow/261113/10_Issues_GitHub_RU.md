## Как работать над Issue: Александра и Настя (с Claude Code)

1. Назначь Issue на себя («Assignees»).
2. Открой Claude Code в папке проекта, скопируй блок «Текст для Claude», впиши номер Issue вместо `___` и отправь.
3. Claude покажет план. Если понятно, ответь «да». Если нет, спроси, что значит непонятное слово.
4. Когда Claude закончит, сама пройди «Как проверить».
5. Claude открывает PR. Ссылку отправь проверяющей в чат команды.
6. После «Проверено» в PR нажми «Merge». Issue закроется сам.

## Как работать над Issue: Дмитрий (без ИИ)

1. Назначь Issue на себя.
2. Выполняй шаги «Что сделать» по порядку. Команды копируй целиком.
3. Если команда выдала ошибку, ничего не удаляй. Скопируй команду и весь текст ошибки в комментарий к Issue. Ответят Александра или Настя.
4. Документы (`docs/...`) создавай на сайте GitHub: «Add file → Create new file», внизу «Create a new branch», «Propose changes», потом «Create pull request».

## Как работать над Issue: Геннадий (бесплатный ИИ, без репозитория)

1. Назначь Issue на себя.
2. Проект на компьютер получаешь через GitHub Desktop: «Fetch origin», потом «Pull». Сам ничего в GitHub не отправляешь.
3. Коллекция Postman лежит в проекте: `api/postman/jasno.postman_collection.json` и `api/postman/local.postman_environment.json`. После каждого обновления проекта импортируй её заново, старую в Postman удали.
4. Бесплатный ИИ-чат (ChatGPT, Claude, Gemini) можно спрашивать, что значит ошибка или проверка. Нельзя вставлять туда файл `.env`, ключи API и тексты настоящих писем.
5. Результат пиши комментарием в Issue: что запускал, сколько проверок зелёных и красных, скриншот Runner.
6. Каждую ошибку оформи отдельным Issue по шаблону.

### Шаблон Issue об ошибке

```text
Заголовок: [BUG] <коротко, что не так>

Какой запрос: <папка и имя запроса в Postman>
Что ожидалось: <например, 401 INVALID_CREDENTIALS>
Что пришло: <статус-код и текст ответа целиком>
Как повторить: <шаги>
Версия: <дата, когда делал Pull>
```

Метки: `bug`, `area:backend`. Исполнителя назначат Александра и Настя.

## Словарик

- Репозиторий: папка проекта в GitHub со всей историей изменений.
- Ветка: отдельная копия кода для одной задачи. Основная ветка `master`.
- Коммит: сохранённый шаг работы с коротким описанием.
- Pull Request (PR): просьба перенести изменения из своей ветки в `master`. Его проверяют другие. Merge: перенос проверенного PR.
- Бэкенд (`api/`): программа на сервере. Хранит данные, говорит с ИИ, отвечает на запросы.
- Фронтенд (`web/`): сайт, который человек видит в браузере.
- Эндпоинт: адрес на сервере, например `POST /auth/login`.
- Swagger: страница `http://127.0.0.1:3000/docs`, где можно вручную вызвать любой эндпоинт.
- Postman: программа для запросов к серверу с автоматическими проверками. Коллекция: набор запросов. Runner: запуск коллекции подряд.
- База данных: место, где сервер хранит кабинеты, дела, письма. SQLite (один файл) для разработки, PostgreSQL для публикации.
- Prisma: библиотека для работы с базой. Таблицы описаны в `api/prisma/schema.prisma`. Prisma Studio: страница в браузере с таблицами.
- Факт (claim): то, что Ja!sno нашёл в письме, с цитатой. Человек подтверждает его или отклоняет.
- Токен сессии: длинная случайная строка, которую сервер выдаёт после входа.
- Статус-код: 200/201 «получилось», 204 «получилось, ответ пустой», 400 «неверные данные», 401 «не вошёл», 404 «не найдено», 409 «уже существует» или «нельзя сейчас», 422 «не удалось обработать», 429 «слишком много попыток», 500/502 «ошибка на сервере или у ИИ».
