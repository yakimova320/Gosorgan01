# Демо Ja!sno: runbook

Как подготовить и показать Ja!sno на демо (25.11) и защите (03.12). Все данные синтетические: письма из `fixtures/letters`, человек «Alex Beispiel», адреса «Muster…/Beispiel…». Настоящие письма и данные людей не загружать.

## 1. Подготовка (один раз, за день до показа)

1. Свежий `master`, зависимости и база — по README, раздел «Быстрый запуск»:

   ```bash
   pnpm install
   pnpm db:up
   pnpm db:migrate
   ```

2. В `api/.env` вписать пароль демо-кабинета (не меньше 10 знаков; файл в git не попадает):

   ```
   DEMO_EMAIL=demo@example.org
   DEMO_PASSWORD=…
   ```

   Пароль знают только те, кто показывает. В репозиторий, Issue и чат его не писать.

3. Создать демо-кабинет:

   ```bash
   pnpm db:seed
   ```

   Ожидаемый вывод: «Демо-кабинет создан: demo@example.org, дел: 3, просроченных сроков: 1.»

   - Модель внутри seed всегда demo: сеть и ключ модели не нужны, `api/.env` не меняется.
   - Повторный `pnpm db:seed` пересоздаёт только демо-кабинет (с пометкой demo в базе) — так же можно сбросить демо после показа. Обычный аккаунт с тем же e-mail seed не трогает и останавливается с сообщением.
   - В production seed не запускается.

## 2. Что в демо-кабинете

| Дело | Письмо | Что показать |
|---|---|---|
| Jobcenter Musterstadt, JC-2026-1001 | `01_jobcenter_request.pdf` | просьба прислать выписки, срок 30.11.2026 |
| Bürgeramt Beispielhausen | `04_buergeramt.pdf` | требование и срок 02.12.2026 |
| Finanzamt Beispielhausen | `12_past_deadline.pdf` | срок 01.10.2026 — **просрочен** |

Все факты подтверждены, у каждого письма готово объяснение.

## 3. Запуск перед показом

```bash
pnpm dev:api
```

```bash
pnpm dev:web
```

Открыть `http://localhost:5173`, «Войти»: `demo@example.org` и пароль из `DEMO_PASSWORD`. В углу должно быть «сервер»; жёлтой плашки «Примерные данные» быть не должно.

Показ с телефона: README, раздел про телефон в той же сети (адрес Mac вместо `localhost`, `HOST=0.0.0.0` только дома, после показа вернуть).

## 4. Сценарий показа (около 5 минут)

1. **Кабинет**: три дела, у Finanzamt — просроченный срок.
2. **Дело Jobcenter** → «Объяснение»: о чём письмо, что сделать, срок; у каждого пункта видно, на какие факты он опирается.
3. **«Проверить факты»**: каждый факт с цитатой из письма; дата есть в цитате. Можно показать «Исправить» (новая версия факта, объяснение сбрасывается).
4. **«Подготовить ответ»** → «Задать вопрос ведомству» → выбрать вопрос → «Собрать черновик»: немецкий текст из подтверждённых фактов, отчёт проверки.
5. **«Скопировать немецкий текст»**.
6. По желанию — **новое письмо**: «Новое письмо» → загрузить `fixtures/letters/06_multiple_deadlines.pdf` (или фото синтетического письма) → факты → «В дело».
7. Сбросить демо после показа: `pnpm db:seed`.

## 5. Запасной вариант: модель недоступна

Если провайдер модели перегружен («Ja!sno сейчас перегружен») или нет сети для модели:

1. В `api/.env` поставить `LLM_MODE=demo`, перезапустить `pnpm dev:api`.
2. Сайт и база остаются настоящими: вход, дела, объяснения из демо-кабинета, черновик и копирование работают как обычно. Новое письмо читает demo-модель: факты берутся из примера синтетических писем, а не из настоящей модели — об этом сказать вслух.
3. После показа вернуть `LLM_MODE=openai`.

Показ дел, объяснений и черновиков демо-кабинета модель не вызывает: объяснения сохранены заранее. Исключение: после «Исправить» в фактах объяснение запрашивается заново — нужна модель или `LLM_MODE=demo`.

## 6. Если что-то не работает

| Признак | Что сделать |
|---|---|
| `Seed не выполнен: Нет DEMO_PASSWORD` | вписать `DEMO_PASSWORD` в `api/.env` |
| `Аккаунт … — обычный, не демо` | этот e-mail занят обычным аккаунтом: указать другой `DEMO_EMAIL` |
| «Нет связи с сервером» | открыт не `http://localhost:5173` (например `127.0.0.1`) или API не запущен: `curl http://127.0.0.1:3000/health` |
| Неверный пароль при входе | пароль из `DEMO_PASSWORD` того `api/.env`, с которым запускался seed; при сомнении снова `pnpm db:seed` |
| «Лимит: не больше 30 писем…» | лимит операций с моделью за 24 часа (B18); для показа достаточно, сброс — `pnpm db:seed` |
